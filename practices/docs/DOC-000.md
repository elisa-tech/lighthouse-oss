# Documentation

Documentation describes how the project records and communicates
information needed to use, develop, maintain, integrate, and assess the
software. It enables adoption, contribution, maintenance, and assessment.
It reduces reliance on tacit knowledge and helps external users understand
whether the project is suitable for their context.

For safety- or compliance-relevant use, documentation is also part of the
evidence base.

## Scope

Documentation includes:

- user documentation
- installation and configuration guides
- developer documentation
- contribution guides
- architecture documentation
- API/interface documentation
- coding and review guidance
- release notes
- known limitations
- process documentation
- assessment and audit evidence
